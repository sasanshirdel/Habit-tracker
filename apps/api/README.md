# @habit/api

NestJS 12 (ESM) REST API — the modular monolith backend. Currently contains:

- `GET /api/v1/health` liveness and `GET /api/v1/health/ready` readiness (PostgreSQL + Redis checks; 503 when either is down)
- zod-validated environment configuration (`src/config/env.ts`) — the app fails fast on invalid config; `DATABASE_URL` and `REDIS_URL` are required (separate schema for the worker)
- `DatabaseModule` / `PrismaService` (`src/database/`) — Prisma 7 with the `pg` driver adapter
- Prisma schema (`prisma/schema.prisma`, `prisma.config.ts`) and migrations (`prisma/migrations/`: baseline, then identity tables from P2-01 — ADR-0017, habit tables from P3-01 — ADR-0028, schedule versioning from P3-03 — ADR-0030)
- API conventions (`src/common/`, P1-05, ADR-0009): `requestIdMiddleware` (`x-request-id` on every response, `currentRequestId()`), global `AllExceptionsFilter` (`{ error: { code, message, details?, requestId } }`, `ApiException`), `ZodValidationPipe` (400 `VALIDATION_FAILED` with field-level issues), cursor pagination helpers (`paginate`, `encodeCursor`/`decodeCursor`, `sortSchema`); JSON body limit 100 kB. `configureApp()` applies them in `createApp` and in tests.
- Structured logging (`src/common/logging/`, P1-07, ADR-0010): `JsonLogger` is Nest's logger — JSON lines with `requestId`/`userId` (request) or `jobId`/`jobName`/`attempt` (job), one access line per request (`accessLogMiddleware`), mandatory redaction (`redact`, `scrubText`; error messages only with `NODE_ENV=development`), `LOG_LEVEL`/`LOG_FORMAT`. Keep using `new Logger(Context)`; log objects as `logger.log({ msg, ...fields })`; call `setRequestUserId(id)` once a user is authenticated (P2-03).
- Identity (`src/modules/identity/`, ADR-0017/0018): tables + secret-token primitives (P2-01); `IdentityModule` with `AuthController` (`/auth/register|login|logout|logout-everywhere`), `AuthService`, `PasswordHasher` (Argon2id on `node:crypto`), `LoginThrottle` (per-email lockout in Redis; tests use `MemoryLoginThrottleStore` via `overrideProvider(LOGIN_THROTTLE_STORE)`), `SessionService` (create/resolve/revoke); since P2-03 (ADR-0019) also the global `AuthGuard` (deny by default + CSRF), `RequestSessionResolver` and `GET /auth/session`; since P2-08 (ADR-0023) `AccountController` (`/account/sessions`, `/account/sessions/{id}`, `/account/sessions/revoke-others`, `/account/security-events`), `SecurityEventService` (record inside the caller's transaction) and the coarse User-Agent classifier `client-description.ts`; since P2-07 (ADR-0024) `ProfileController` (`GET`/`PATCH /account/profile`, `/account/preferences`) and `ProfileService`; since P2-10 (ADR-0025) `PrivacyController` (`POST /account/export`, `POST /account/deletion`), `AccountRestoreController` (`POST /auth/account-restore`), `AccountDeletionService`, `AccountRestoreService`, `AccountPurgeService`, the worker handlers `identity.account-deleted-email` / `identity.account-purge`, and `IdentityDataExportContributor` (the `account` section of the export).
- Habits (`src/modules/habits/`, P3-01, ADR-0028): habit tables (categories, habits, schedule versions, recorded occurrences, notes, pauses), `HabitsModule` with the owner-scoped `HabitRepository` (no routes yet — P3-06), `toDbDate`/`fromDbDate` (the only local-date conversions) and row ↔ contract mappers, `HabitsDataExportContributor` (the `habits` section of the export). Schedule versioning (P3-03, ADR-0030): `HabitScheduleService.changeSchedule` (internal, no route yet) splits or replaces versions from an effective date in one locked transaction, refuses unsafe changes with `HabitScheduleChangeError` codes, requires a reason for historical corrections and appends to the `habit_schedule_changes` audit trail; the pure rules are `planScheduleChange` (`schedule-versioning.ts`). Uses `@habit/habit-engine` at runtime ("today" in the profile time zone, version checks).
- Data export (`src/data-export/`, P2-10, ADR-0025): platform `DataExportModule` (global) with `UserDataExportRegistry` — every feature module with user rows registers one `UserDataContributor` (section, tables included/excluded, `collect(tx, userId)`) — and `UserDataExportService` (one read-only repeatable-read snapshot). Purge: until a job scheduler exists, enqueue `identity.account-purge` (`ACCOUNT_PURGE_JOB`, empty payload) once a day from the deployment.
- Authentication markers (`src/common/auth/`, P2-03, ADR-0019): every route is protected unless `@Public()` (or `@Public({ session: 'optional' })`); add a public route to the reviewed list in `test/route-guards.e2e.test.ts`. Use `@CurrentUser()` for the principal and `ownedBy(user)` + `foundOr404()` for customer-owned rows. State-changing requests need an allowed `Origin` and, with a session, `X-CSRF-Token`; tests mounting extra controllers on `AppModule` mark them `@Public()` unless they test authentication.
- Security (P1-08, ADR-0011): `securityHeadersMiddleware` (first middleware; deny-all CSP, HSTS, `nosniff`, `no-store`, …), CORS via `corsDelegate` (exact `CORS_ORIGINS`), `RateLimitModule` (`src/rate-limit/`): global guard with Redis counters — `default` on every route, add `@RateLimit('auth')` to credential/code endpoints and `@RateLimit('expensive')` to costly ones, `@SkipRateLimit()` for probes only; 429 `RATE_LIMITED` + `Retry-After`. Env: `RATE_LIMIT_ENABLED`, `RATE_LIMIT_PREFIX`, `TRUST_PROXY`. Tests swap the store for `MemoryRateLimitStore` (`overrideProvider(RATE_LIMIT_STORE)`).
- OpenAPI (`src/openapi/`, P1-06, ADR-0012): OpenAPI 3.1 generated from the routes' zod schemas — inputs from their `ZodValidationPipe`s, responses from `@ApiDoc({ operationId, summary, responses })`; group with `@ApiTag`, hide with `@ApiExclude()` (**required** for `/admin` routes — the generator refuses to publish them). Every route needs `@ApiDoc` or `@ApiExclude`, or the unit test and CI export fail. Publish reusable response schemas with `component(schema, { id })`. Served as JSON at `GET /api/docs/openapi.json` (no HTML UI; not rate-limited) unless `NODE_ENV=production`; env `API_DOCS_ENABLED` overrides (production only with an explicit `true`). `pnpm --filter @habit/api openapi:export [out]` writes `dist/openapi.json` from the built app without a database or Redis; CI uploads it as the `openapi` artifact.
- `QueueModule` (`src/queue/`, P1-03) — shared ioredis connection, `QueueProducer.enqueue(definition, payload)` (validates the payload, fails fast with `QUEUE_UNAVAILABLE` when Redis is down, optional idempotent `jobId`), job definitions via `defineJob`, Redis readiness check. Example job: `system.noop`.
- `WorkerModule` (`src/worker/`, P1-03) — consumers run by `apps/worker`: `JOB_HANDLERS`, payload re-validation (invalid/unknown jobs fail without retry), `WorkerHost` (one BullMQ worker per queue, graceful drain bounded by `WORKER_SHUTDOWN_TIMEOUT_MS`).

### Background jobs

A module that needs background work:

1. defines its job next to its code: `export const X_JOB = defineJob({ name: '<module>.<action>', queue: 'system', schema: z.strictObject({...}) })` — payloads carry **IDs and small parameters only**, never personal content (SECURITY.md);
2. enqueues from its service with `queueProducer.enqueue(X_JOB, payload, { jobId? })` and handles `QueueUnavailableError`;
3. implements a `JobHandler` (idempotent — a job can run more than once) and adds it to `JOB_HANDLERS` in `WorkerModule`.

Defaults: 3 attempts, exponential backoff from 1 s; failed jobs stay in the failed set for 7 days.

Package exports for `apps/worker`: `@habit/api/queue` and `@habit/api/worker` (built `dist/`, see ADR-0002 addendum).

```bash
pnpm --filter @habit/api dev                  # watch mode (nest CLI), regenerates the Prisma client
pnpm --filter @habit/api build                # prisma generate + tsc -> dist/
pnpm --filter @habit/api start                # node dist/main.js
pnpm --filter @habit/api openapi:export       # after build: dist/openapi.json (no DB/Redis needed)
pnpm --filter @habit/api test                 # vitest (unit + supertest e2e) — no database needed
pnpm --filter @habit/api test:integration     # real PostgreSQL (DATABASE_URL, throwaway DB) + Redis (REDIS_URL, per-run key prefix), incl. queue → worker
pnpm --filter @habit/api db:migrate:deploy    # apply migrations
pnpm --filter @habit/api db:migrate:dev --name <change>   # create a migration (local only)
DATABASE_URL=postgresql://... pnpm --filter @habit/api prisma:validate
```
